# game3 v5 수정·검증 보고서

기준: 사용자가 제공하고 로컬에 압축 해제한 `game3-main.zip`. GitHub 최신 HEAD와의 일치는 네트워크 제한 때문에 검증하지 못했습니다. main 브랜치나 원격 배포는 변경하지 않았습니다. 이번 ZIP에는 수정된 실행 프로젝트, 원문·수정 스토리 자료, 변경표, 테스트와 측정 근거가 들어 있습니다.

## 1. 구현 구조와 진단

| 영역 | 실제 구현 | 문제·개선 |
|---|---|---|
| 호스트 | `app.py`, Streamlit custom component, 실제 사용 경로 `frontend/` | Python은 사건 선택 때만 상태를 갱신. 이동의 Python 호출은 원래 없었으므로 새로 해결했다고 주장하지 않음 |
| 상태 | `engine.py`의 `new_state`, `apply`, `ready`, `recap` | nonce 중복 방지에 화면 리비전 검사를 추가. 이미 끝난 finish 재실행 차단 |

| 이동·충돌 | 타일 이동, 145ms 간격, 건물 사각형·ㄱ자 학교 복도 충돌 | 프레임 반올림으로 저 FPS에서 이동이 느려짐. 누적 시간 기반 간격과 첫 입력 즉시 반영 |
| 에셋 | PNG 아틀라스·학교·실내·교사 이미지 | 모든 장면을 시작 때 로딩. 현재 장면만 로딩하고 재사용하도록 변경 |
| 스토리 | `content.py`의 16개 사건, 16명 NPC, 19→43→69세 | 생애 연령, 사건·선택 ID 유지. 핵심 인구 사건 누락 경로를 차단 |

`component/frontend/`는 과거 엔진용 미사용 경로이며 현재 앱은 이를 호출하지 않습니다. 폴더를 다른 게임으로 바꾸거나 엔진을 교체하지 않았습니다. 사용자 작업 폴더 안의 중복 중첩 `game3-main/`은 최종 ZIP에 재포함하지 않았습니다.

## 2. 성능 측정과 범위

Chrome/154.0.8037.99, Windows headless, GPU 비활성화. PC 크기 1320×1000, 태블릿 크기 810×1100, CPU 1×/4×. 각 장면·조건별 2.1초씩 3회, 표는 3회 중앙값입니다. Canvas·PNG는 실제 Chrome으로 실행했습니다. HTTP 대신 원본 PNG를 data URI로 넣었으므로 **실제 다운로드·서버 응답·기기 성능 결과가 아닙니다**. CPU 제한은 태블릿 실기기를 대신하지 않습니다.

수정 전부터 FPS가 약 60으로 유지되어 FPS 증가 효과는 확인되지 않았습니다. draw 시간도 일관된 개선으로 확인되지 않았으며 일부 구간 증가했습니다. 절대 시간은 작은 범위지만, 전체 렌더링이 더 빨라졌다고 결론내리지 않습니다. 결과가 없었던 배경 캔버스 복제 최적화는 제거했습니다. 학교 인덱스는 반복 배열 생성과 조회를 줄이는 수준입니다.

### 확인된 이동·시작 비용 개선

| 항목 | 이전 | 수정 |
|---|---:|---:|
| 초기 요청 이미지 수 | 76 | 13 |
| 초기 요청 파일 용량 합계 | 7,209,439 bytes | 698,143 bytes |
| 2.9초 입력, 60 FPS 시간표 | 19칸 | 20칸 |
| 2.9초 입력, 30 FPS 시간표 | 17칸 | 20칸 |
| 2.9초 입력, 15 FPS 시간표 | 14칸 | 20칸 |

초기 파일 합계가 90.3% 줄었습니다. 이는 실제 로딩 시간을 재어 얻은 감소율이 아니라 소스가 요청한 파일들의 크기 합입니다. 그래픽 원본은 78개 PNG 모두 업로드 ZIP과 바이트가 동일합니다. 필요할 때 나머지 장면을 로딩하므로 전체 설치 에셋 용량은 줄이지 않았습니다.

이동 실험은 동일 시간표로 `updateMovement`를 호출해 실제 이동 칸 수를 비교했습니다. 기본 145ms/칸을 유지하며 프레임에 따른 추가 지연을 제거했습니다. 실제 터치→화면 지연, 최초 HTTP 로딩 시간, 맵 전환의 네트워크 시간, GPU 메모리는 미측정입니다. 원시 결과에는 FPS 하위 1% 근사(프레임 p99의 역수), 프레임 p50/p95, draw 시간, 관찰 JS heap도 포함합니다.

### 저장 병목

SQLite 저널 개선 직전과 WAL 적용 후의 동일 가상 전체 플레이 저장 시나리오입니다. 각 학생은 시작부터 소감문까지 15번 저장했습니다. 10·20·30개 작업 스레드이며 실제 Streamlit 동시 접속 부하는 아닙니다. 연결은 매 작업 후 닫고 FULL synchronous 내구성을 유지합니다.

| 가상 학생 | 저장 수 | 저장 p95 ms, WAL 전→후 | 수정 후 p50 ms | 분리된 완료 상태 |
|---|---|---|---|---|
| 10 | 150 | 377.5 → 106.9 | 2.6 | 10 |
| 20 | 300 | 653.6 → 337.2 | 2.3 | 20 |
| 30 | 450 | 960.7 → 658.3 | 3.5 | 30 |

실제 Sheets 네트워크·서비스 할당량·동시 append 충돌은 미검증입니다. 같은 게임을 여러 기기에서 동시에 선택하는 상황의 트랜잭션 충돌까지 해결했다고 주장하지 않습니다. 동일 게임의 늦게 도착한 낮은 리비전·중복 스냅샷을 읽어 진행을 되돌리는 문제는 SQLite 및 모의 Sheets로 검증했습니다.

## 4. 전체 스토리 평가

전체 사건·선택·NPC 원문은 `V5_STORY_DATA.json`, 도달 가능 관계는 `V5_EVENT_GRAPH.json`입니다. 기본 16개 사건에 직업·주거, 청년 이동·카페, 돌봄·일생활·어린이집·노동·정책, 세대·정원·축제, 노후 네 영역이 있습니다. 필수 경로는 기존 8개에서 10개로 늘렸고 임의 순서 탐험은 유지했습니다.

## 5. 교육 콘텐츠의 실제 변경

핵심 세 사건에서 **상황 관찰 → 주민 세 관점 → 대응 선택 → 지표/시설 안내 변화 → 재방문·엔딩에서 효과와 남은 과제 확인** 흐름을 구현했습니다. 주민 의견은 UI에서 모두 열어야 선택이 활성화됩니다. 서버에는 관찰 기록도 남지만 이를 실제 이해도 점수로 취급하지 않습니다.

- `nursery`: 지역의 아이·학교·상점 감소를 고용·주거·돌봄과 연결. 공간 공동 사용, 교직원 전환, 교육비 지원. 출생아 증가를 즉시 보상으로 계산하지 않음.
- `care`: 고령 주민의 독립 생활, 가족 노동, 전문 인력·의료 접근성 비교. 공동 돌봄, 근무 조정, 방문 돌봄/진료. 비용과 전문 지원의 한계를 함께 표시.
- `labor`: 생산가능 연령대와 청년 유출, 영업시간·채용·노동환경 변화. 훈련, 고령 친화 일자리, 휴식·안전. 훈련의 후속 효과는 다음 생애 시기에 반영.
- `policy`: 기존 네 선택 유지. 다른 사건과 공유하는 재정 여력·지역경제·교육보육·일자리·돌봄·교류로 반영. 어떤 가족 형태에도 도덕 점수나 출산율 가산을 부여하지 않음.

지표 범위 0~12는 수업용 가상 값입니다. 현실 통계나 인구 예측, 가족 선택의 성적표가 아닙니다. 개별 choice의 원문·새 대사·목표·상태 효과·후속 효과는 `V5_EVENT_CHANGES.md`와 스토리 JSON에서 확인할 수 있습니다.

엔딩은 실제 직업·주거·정책·돌봄과 네 노후 준비 선택을 보여 줍니다. 이전의 노후 항목 내부 ID 표시를 선택 내용으로 바꿨습니다. 실제 선택의 긍정 효과와 남은 과제, 후속 대사를 함께 제공합니다. 소감문 질문 세 개는 사건의 영향·대응 결과·나의 미래 준비를 묻고 기존 소감/CSV/Sheets state JSON에 저장됩니다.

## 7. 실행·남은 확인

실행은 `pip install -r requirements.txt` 후 `streamlit run app.py`로 동일합니다. `V5_START_HERE.md`에 수업 운영안·저장·검증 명령을 정리했습니다. Google Sheets 인증정보나 실제 학생 데이터를 결과물에 넣지 않았습니다.

필요한 현장 검증: 실제 iPad Safari/Android Chrome의 회전·장기 입력·저장 복원, 실제 Sheets 인증/네트워크 재시도와 동시 수업, 학생 플레이 시간·소감문 평가. ZIP 소스는 수정했지만 원격 GitHub 커밋/PR·배포는 수행하지 않았습니다.
